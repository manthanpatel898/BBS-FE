# Post-event Settlement

Super Admin can enable this default-off add-on on a BANQUET company. Booking details refresh the live company flag on open, window focus and returning to a visible tab and fail closed if it cannot be loaded. Confirmed or completed events before today in Asia/Kolkata expose Record Payment to existing payment users and Settlement Discount to users with `bookings.settlement.manage`. Ordinary booking editing remains locked.

Payment entry includes an actual payment date, reset for every new record. Settlement requires a positive amount no larger than pending and a reason, with final and pending previews and an invoice cancellation/reissue notice. Existing settlement totals and actor/date/reason history remain visible in details and customer booking prints after disabling the add-on. Booking discount remains separate. The server authorizes every mutation against the live entitlement.

Settled invoice issue/reissue uses the server preview’s combined booking and settlement discount. The invoice discount controls are locked; existing issued snapshots remain displayed until replacement mode is selected. Past-event payment corrections require the same live add-on entitlement plus the existing edit/delete permission.

Event details use one scrolling body containing readable settlement history and WhatsApp communication, with a fixed action footer. Financial Summary highlights Final Bill, Total Received and Pending (Fully Paid in green); Bill breakdown expands package charges, booking discount, original bill and cumulative settlement discount. Zero excess is hidden. Payment History labels all receipts consistently.

Eligible staff see Add Settlement Discount beside history for every additional adjustment while pending remains positive; zero balance keeps the action disabled with an explanation. Revoking the entitlement hides mutation actions while preserving existing history. Reason suggestions and an optional note compose the existing reason field without changing historical entries. Payment row actions collapse under Actions, and edit/delete confirmation shows the affected amount and resulting pending balance, including excess payments. Print, Kitchen Print and optional Print Tag share an upward opening footer menu.
